# SC Forms — независимые формы для PHP-сайта

Автономный PHP-скрипт для показа форм в модальном окне или непосредственно на странице и отправки заявок через SMTP. Доступны пять форм: `consultation`, `requestdemo`, `becomeclient`, `partner`, `feedback`.

## Структура проекта

```text
public/                    Демо, PHP-обработчик, JS, CSS и шрифты
config/config.example.php  Пример конфигурации и переменные окружения
config/config.local.php    Локальные настройки (не включаются в Git)
config/forms/              Поля, подписи, согласия и шаблоны сообщений
src/                       Рендеринг, валидация, защита и отправка почты
tests/                     Проверки PHP, HTTP, SMTP и браузера
docs/                      Проектные документы и отчёты проверок
var/                       Данные ограничения частоты и временные данные тестов
vendor/                    Зависимости Composer
```

## Быстрый запуск

Требуются PHP 8.1+, OpenSSL и исходящие подключения к SMTP-серверу. Клиентская часть рассчитана на современные браузеры с `dialog`, `fetch` и `AbortController`.

1. Если папка `vendor` отсутствует, выполните в корне пакета `composer install --no-dev --prefer-dist`. В поставленной сборке зависимости уже включены, `composer.lock` фиксирует версию PHPMailer.
2. Скопируйте `config/config.example.php` в `config/config.local.php`.
3. Укажите `public_url` — источник обработчика, например `https://example.org`, без пути и завершающего `/`; случайный `secret` минимум 32 символа; SMTP и адреса почты.
4. Разместите **только содержимое `public/`** в публичном каталоге сайта. Остальные файлы должны быть вне публичного каталога. В начале `form.php` исправьте `$packageRoot` на абсолютный путь к закрытой папке пакета.
5. Дайте PHP право создавать файлы в `var/`; проверьте доступность временной папки PHP (`sys_temp_dir`). На рабочем сайте отключите `display_errors` и включите `log_errors` в настройках PHP; для PHP-FPM/CGI приложен `public/.user.ini`, для mod_php используйте настройки виртуального хоста. Подключите CSS, JS и кнопку по примеру ниже.

Пример безопасного размещения:

```text
/home/account/sc_forms/             ← config/, src/, vendor/, var/
/home/account/public_html/forms/   ← form.php, assets/, demo.html
```

В публичном `form.php`:

```php
$packageRoot = '/home/account/sc_forms';
```

На Windows пример пути: `$packageRoot = 'W:/Projects/sc_forms';`.

**Не размещайте весь пакет внутри `public_html`**: закрытые настройки и служебные файлы должны оставаться вне доступа через HTTP. Для хостинга без Composer подготовьте `vendor` на компьютере и загрузите вместе с приватной частью. Для локального просмотра при настроенном `config.local.php`: `php -S 127.0.0.1:8099 -t public`; `public_url` при этом `http://127.0.0.1:8099`, страница `http://127.0.0.1:8099/demo.html`.

## Локальное демо

В текущей локальной установке страница демо: `https://testscipts.local/sc_forms/public/demo.html`. В локальной конфигурации задан `public_url = https://testscipts.local` и создан случайный секрет. SMTP наследуется из примера и переменных окружения: перед отправкой задайте сервер, учётные данные, отправителя и получателя. Наличие формы само по себе не подтверждает доставку писем.

Если `config/config.local.php` уже существует, сохраните его настройки; повторное копирование примера не требуется. Этот файл имеет приоритет над примером. В текущем локальном файле адрес сайта и секрет переопределяются после подключения примера.

Для проверки отображения SMTP не нужен. Откройте демо и нажмите одну из пяти кнопок; справа (на узком экране — ниже) загружается встроенная форма обратной связи. Проверьте поля, ссылки на согласия, закрытие модального окна крестиком, Escape и кликом по фону.

При последней проверке локальный веб-сервер возвращал `No input file specified.` по адресу `https://testscipts.local/sc_forms/public/form.php?form=consultation`, хотя прямой запуск обработчика через PHP создавал HTML формы. После исправления настроек сервера отображение в браузере требуется проверить повторно.

## Если форма не загружается

- Откройте `public/form.php?form=consultation` на своём сайте: ожидается HTML формы, а не ошибка сервера.
- `No input file specified.` означает, что PHP не получил доступный путь к файлу. Проверьте корневую папку сайта, соответствие URL реальному файлу и настройку пути скрипта в связке веб-сервера с PHP.
- При HTTP 500 проверьте PHP 8.1+, наличие `vendor/autoload.php`, путь `$packageRoot`, конфигурацию и журнал ошибок PHP. Для загрузки формы требуется секрет не короче 32 символов и корректный `public_url`.
- При HTTP 403 проверьте `public_url` и `allowed_origins`. Адрес источника включает схему и порт, но не путь.
- Если обработчик открывается, а демо показывает ошибку, проверьте `data-endpoint` и сетевые запросы браузера. В демо `../form.php` разрешается относительно `assets/sc-forms.js` и указывает на обработчик внутри `public/`.

## Файлы в Git

`.gitignore` исключает локальную конфигурацию, `.env` и его варианты (кроме `.env.example`), содержимое `var/` (кроме `.gitkeep`), зависимости `vendor/` и `node_modules/`, журналы и локальные файлы редакторов. `composer.json`, `composer.lock`, пример конфигурации, исходники и тесты следует хранить в репозитории. Сам скрипт не загружает `.env`: переменные должны быть доступны процессу PHP.

При развёртывании установите зависимости Composer и создайте локальную конфигурацию отдельно. `.gitignore` не прекращает отслеживание файлов, которые уже добавлены в Git.

## Подключение к странице

```html
<link rel="stylesheet" href="/forms/assets/sc-forms.css">
<script defer src="/forms/assets/sc-forms.js"
        data-endpoint="/forms/form.php"></script>

<button type="button" data-sc-form="consultation">Записаться на консультацию</button>
<button type="button" data-sc-form="requestdemo">Запросить демо</button>
<button type="button" data-sc-form="becomeclient">Стать клиентом</button>
<button type="button" data-sc-form="partner">Стать партнёром</button>
<button type="button" data-sc-form="feedback">Обратная связь</button>

<!-- Форма непосредственно на странице -->
<div data-sc-form-inline="feedback"></div>
```

`data-endpoint` может быть абсолютным URL другого сайта. Относительный адрес разрешается относительно URL JS-файла; адрес с `/` — относительно его домена. При загрузке JS с другого домена удобнее задавать полный URL обработчика.

После загрузки скрипта доступно:

```js
SCForms.open('consultation');
SCForms.close();
// Для контейнеров, добавленных на страницу динамически:
SCForms.init();
// При необходимости переопределить адрес:
SCForms.init({endpoint: 'https://example.org/forms/form.php'});
```

Модалка закрывается крестиком, Escape и кликом по фону. Фокус возвращается на кнопку. Кнопки, добавленные динамически, работают без повторной инициализации. Ошибки сохраняют введённые данные. При истечении токена предлагается обновить форму; это действие сбрасывает ввод.

Для старых страниц поддерживаются `.js-showForm-consultation` и событие `jQuery(document).trigger('openForm', ['consultation'])`. Если jQuery подключён позже SC Forms, вызовите `SCForms.init()` после его загрузки. **Старый `form.js` отключите**, иначе он тоже отправит запрос. Старый `js.js` может оставаться для других функций сайта, но новой модалке он не нужен. Теги `{SCForm}…{/SCForm}` замените контейнерами `data-sc-form-inline`.

## SMTP и конфигурация

В `config/config.local.php`:

```php
<?php
return [
    'public_url' => 'https://example.org',
    'allowed_origins' => [],
    'secret' => 'ЗАМЕНИТЕ_СЛУЧАЙНОЙ_СТРОКОЙ_ОТ_32_СИМВОЛОВ',
    'storage' => dirname(__DIR__) . '/var/rate',
    'rate_limit' => 5,
    'rate_window' => 3600,
    'smtp' => [
        'host' => 'smtp.example.org',
        'port' => 587,
        'encryption' => 'tls',
        'auth' => true,
        'username' => 'forms@example.org',
        'password' => getenv('SC_SMTP_PASSWORD'),
        'timeout' => 15,
    ],
    'mail' => [
        'from_email' => 'forms@example.org',
        'from_name' => 'Мой сайт',
        'to' => ['manager@example.org'],
    ],
];
```

`tls` — STARTTLS, обычно порт 587; `ssl` — SMTPS, обычно 465. Проверка сертификатов включена. Пустое шифрование разрешено только для `localhost`, `127.0.0.1`, `::1` в локальных тестах. Email посетителя попадает в Reply-To; From должен быть разрешён вашим SMTP-провайдером. Тема берётся из настроек формы. Если `mail.to` и отправитель равны `null`, используются демонстрационные адреса из `config/forms/*Opt.php`: перед первым рабочим запуском замените их своими адресами. Ссылки `/policy` и `/consent` ведут на страницы текущего сайта; разместите там свои документы или измените ссылки в настройках форм и `src/Forms.php`.

Секрет можно получить: `php -r "echo bin2hex(random_bytes(32));"`. Не храните секрет и пароль в публичных файлах или Git. Закрытый `config.local.php` исключён из Git. Если используете пример конфигурации напрямую, доступны переменные `SC_FORMS_PUBLIC_URL`, `SC_FORMS_SECRET`, `SC_FORMS_STORAGE`, `SC_SMTP_HOST`, `SC_SMTP_PORT`, `SC_SMTP_ENCRYPTION`, `SC_SMTP_AUTH`, `SC_SMTP_USER`, `SC_SMTP_PASSWORD`, `SC_MAIL_FROM`, `SC_MAIL_NAME`, `SC_MAIL_TO`.

## Другой домен и защита

Добавьте точный источник страницы, например `https://other.example.org`, в `allowed_origins` на сервере. Wildcard и передача cookie не используются. Заголовки CORS выдаются для разрешённых запросов и preflight. Если на сайте задан CSP, разрешите URL обработчика в `connect-src`, а ресурсы — в `script-src` и `style-src`.

Токен формы действует час и подписан серверным секретом; подпись привязана к имени формы. Это не авторизация посетителя: публичные формы доступны всем. Защита включает скрытое поле, проверку полей на сервере, ограничение тела запроса 32 KiB и 5 валидных по токену попыток с одного IP за час (включая ошибки заполнения/SMTP). Ограничение атомарно, действует на все формы вместе, использует хеши IP и ограниченное число файлов. Оно не заменяет полноценную защиту от распределённого спама. За reverse proxy используется `REMOTE_ADDR`; настройте реальный IP на веб-сервере, не доверяйте произвольным `X-Forwarded-For`.

Пользовательский HTML экранируется в письме. Поля выбираются только из конфигурации; пути из запроса не подключаются. Отладочная cookie оригинального плагина и скрытое перенаправление писем не перенесены. Подробности ошибок и SMTP-реквизиты не возвращаются посетителю. В PHP error log пишется категория сбоя без данных заявки и паролей. Ограничьте/ротируйте журналы средствами хостинга. При сетевом обрыве после отправки письмо могло уйти: интерфейс предупреждает перед повторной попыткой, гарантии exactly-once нет.

## Изменение форм

`config/forms/*Opt.php` сохраняют формат настроек оригинала. В них меняются поля, подписи, ссылки на согласия, тема и сообщение успеха. HTML в сообщении успеха считается доверенной настройкой администратора. Типы полей: text, email, tel, textarea, checkbox; `validate => email` дополнительно задаёт email-валидацию. Обязательные согласия проверяются на точное настроенное значение. Максимум для обычного поля — 1000 байт, для текста — 10000 байт. Для комментария и сертификата действует исходный минимум 2 символа; его можно изменить параметром `minlength` в поле. Исходные шаблоны заменены универсальным рендерером с независимыми стилями. Письмо включает настроенные поля, IP и источник.

Чтобы добавить новое имя формы, добавьте конфиг и зарегистрируйте имя в `Forms::NAMES`. Скрипт не подключает произвольные PHP-файлы по имени из URL.

## HTTP-интерфейс

`GET /forms/form.php?form=consultation` — HTML формы с токеном.

`POST /forms/form.php` — URL-encoded поля `form`, `token`, `send=Y`, пустое `website`, `scform[email]`, остальные `scform[...]`.

Ответ: `{"CODE":200,"mess":["…"],"errors":{}}`. Реальный HTTP-статус совпадает с CODE: 400 — неверный формат, 403 — источник/токен, 404 — неизвестная форма, 405 — метод, 413 — размер, 422 — поля/антиспам, 429 — частота, 500 — конфигурация/SMTP. GET никогда не отправляет письмо. Ответы не кешируются.

## Проверки

```sh
composer test
node --check public/assets/sc-forms.js
node tests/http-live.cjs
```

PHP-тесты проверяют формы, валидацию, токены, источники, ограничение частоты, HTTP-контракт и реальное SMTP-взаимодействие на loopback-сервере, который не пересылает письма. Нужны разрешённые локальные сокеты и `proc_open` в CLI. `http-live.cjs` требует Node 18+ и проверяет полный путь HTTP → PHP → SMTP на порту 8101. Для DOM-проверки: установите jsdom отдельно, затем `node tests/dom.cjs` (порт 8100). Для проверки в браузере: установите Playwright отдельно, затем `node tests/browser.cjs`; при необходимости `CHROME_PATH` задаёт путь к Chrome, `PHP_BINARY` — PHP. Этот тест открывает собственный локальный сервер на 8099 и не использует рабочие SMTP-реквизиты. Тестовые порты должны быть свободны, а `config.local.php` — отсутствовать, иначе локальные настройки могут перекрыть тестовое окружение.

SMTP-библиотека: [официальный PHPMailer](https://github.com/PHPMailer/PHPMailer), лицензия LGPL-2.1; исходники и лицензия включены в `vendor/phpmailer/phpmailer`. Реальная доставка зависит от SMTP-реквизитов, разрешённого отправителя и настроек домена; рабочая почта при разработке не отправлялась.
